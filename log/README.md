# 기록

> 테마 문서가 "지금의 정리"라면, 이 폴더는 "언제 무엇이 바뀌었고 그때 어떻게 판단했나"를 남기는 곳입니다 · 투자 권유가 아닌 산업 정리 기록입니다

한 달에 파일 하나(`2026-11.md` 형식)를 두고, 그달에 기록할 내용이 생길 때 만듭니다. 파일 안은 두 부분으로 나뉩니다.

## 변화

정기 점검(수동이든 자동이든)에서 테마 문서를 고쳤을 때, 그 커밋에 함께 한 줄씩 추가합니다. git 이력은 "문장이 바뀌었다"만 보여 주므로, 여기에는 "무엇이 왜 중요한가"를 적습니다. 문서를 고치지 않은 점검은 여기에 적지 않습니다(점검 자체의 기록은 GitHub Actions나 루틴 실행 기록에 남습니다).

| 날짜 | 문서 | 바뀐 사실 | 중요도 | 출처 |
|---|---|---|---|---|
| YYYY-MM-DD | [문서 이름](../themes/...) | 한 문장 요약 | 높음·보통·낮음 | URL |

- **중요도 높음:** 테마의 테제, 병목, 일정이 바뀐 경우. `digest` 이슈 알림 대상입니다.
- **보통:** 수치·키 플레이어 갱신처럼 방향은 그대로인 경우.
- **낮음:** 표현 정리, 출처 보강.

## 내 판단

저장소 주인이 테마·이슈에 대해 내린 판단입니다. **사용자가 직접 말한 판단만** 적고, Claude가 판단을 지어내거나 대신 채우지 않습니다. 자동 갱신은 이 부분을 건드리지 않습니다. 이미 적힌 판단은 고치지 않고, 나중에 확인한 결과는 "이후 결과"에 날짜와 함께 덧붙입니다.

```markdown
### YYYY-MM-DD · [관련 문서](../issues/...)

- **판단:** 산업·테마 수준의 판단 한두 문장
- **근거:** 그렇게 본 이유
- **다시 볼 때:** 판단을 다시 확인할 시점이나 조건
- **이후 결과:** (나중에 덧붙임) YYYY-MM-DD 무엇이 확인됐는지
```

**적지 않는 것:** 개별 종목의 매수·매도·보유 여부, 보유 수량·비중, 목표 가격, 개인 자산 정보. 판단은 "이 병목이 내년까지 풀리지 않을 것", "이 테마는 관찰 단계에 머물 것"처럼 산업과 테마 수준으로만 씁니다.
